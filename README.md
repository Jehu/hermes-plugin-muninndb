# muninnDB Memory Provider for Hermes

A local, self-hosted memory provider plugin for [Hermes Agent](https://github.com/NousResearch/hermes-agent). It stores and recalls memory through the muninnDB REST API.

## Features

- Semantic recall and explicit memory storage
- Read, soft-delete, update, and link engrams
- Background turn sync and prefetch
- Pre-compression insight persistence
- Circuit breaker and retry handling for backend outages
- Optional multi-tenant tagging via `HERMES_TENANT`
- Python standard library only; no runtime dependency installation

## Exposed tools

- `muninn_remember`
- `muninn_recall`
- `muninn_read`
- `muninn_forget`
- `muninn_link`
- `muninn_update`

## Configuration

The plugin uses Hermes' protected local configuration. Do **not** commit it.

`~/.hermes/muninndb.json`:

```json
{
  "host": "localhost:8475",
  "vault": "hermes",
  "threshold": 0.5
}
```

For a locked vault, place `MUNINN_API_KEY` only in `~/.hermes/.env`. A public vault needs no API key.

## Install

Clone this repository into the Hermes user plugin path:

```bash
git clone git@github.com:Jehu/hermes-plugin-muninndb.git ~/.hermes/plugins/muninndb
```

Then select `muninndb` as the active memory provider using `hermes memory setup` or the appropriate Hermes configuration. Fully restart Hermes after updating the plugin; plugin code is loaded at process startup.

## Safety

This repository intentionally excludes credentials, local configuration, generated bytecode, plans, logs, and personal vault inventories.
